# Roadmap with release gates

Release-preparation update: BrainKit 0.2.0 adds a media-production workflow, branding, cover artwork, funding configuration, and contributor templates. This is an additive packaging/capability release; it does not claim the taste/research/voice benchmark milestones below have been completed. Those evidence gates remain in force.

These are dependency-ordered milestones, not calendar promises. Finish a small useful loop before expanding the role list.

| Release | Work | Exit evidence |
|---|---|---|
| 0.1 Foundation | Skills, contracts, installer, source policy, calibration, roadmap | Structural checks and installer isolation pass; behavioral baseline explicitly pending |
| 0.2 Taste and story | Rate six scripts; collect 10 owned writing samples and exact edits; run baseline vs skill | At least 20 held-out tasks across 3 topics; blind preference and failures reported; no invented autobiography |
| 0.3 Research bank | Inspect 30 videos from 5 creator families, including ordinary performers | Every record has modality/provenance; at least 5 matched comparisons; visual claims backed by actual frames |
| 0.4 Voice lab | Audition voices and models on fixed excerpts | At least 3 voices × 2 models with neutral delivery, then 3 deliveries for finalists; blind listener scores and cost logs |
| 0.5 Visual craft | Expand motion, typography, color and thumbnail references | 10 rendered storyboards inspected at phone size and with voice; timing/contrast failures documented |
| 0.6 Measurement | Add opt-in YouTube metadata and owner analytics import | Reproducible import, freshness notes, cohort checks, missing-data handling, no causal claims from raw views |
| 0.7 Distribution | Test client matrix, tagged releases, optional marketplace manifests | Clean install into Claude Code and Codex on fresh projects; clean update/uninstall plan; checksums and migration notes |
| 1.0 Proven workflow | Stabilize contracts and publish honest benchmarks | Repeatable human preference benefit vs baseline, regression suite, contributor workflow, external pilot users |

## First three development sessions

1. **Taste:** choose strongest/weakest lines in calibration; compare the same premise and then test on a different topic. Save scoped preference proposals. Replace fictional events with supplied real material when creating personal stories.
2. **Research:** deeply inspect two creator examples plus one ordinary performer. Annotate an opening, a turn, a payoff, visuals, delivery, and missing evidence. Produce one mechanism transfer test with an original subject.
3. **Voice:** freeze a 45–70-word excerpt. Shortlist voices by listening, not names. Compare model/voice combinations with identical clean text; vary expression only after selecting finalists.

## Study backlog by engine

- **Story:** scene specificity, changing stakes, cause/effect, reveal order, useful omissions, comedic timing, documentary evidence, explainers, multilingual spoken cadence, titles that match payoffs.
- **Research:** transcript accuracy, shot/audio alignment, sponsorship segments, creator-specific recurring choices, selection bias, comparisons within a channel and publication window.
- **Voice:** voice–script fit, breath and pauses, emphasis, expressive range, accent/pronunciation, tag leakage, repeatability, editing continuity, licensing, cost per usable finished minute.
- **Visual:** type measurement, semantic color, contrast, salience, motion purpose, continuity, caption collision, one understandable focal event, accessibility, phone previews.
- **Measurement:** reach vs retention vs satisfaction, Shorts vs long-form, source mix, sample uncertainty, packaging vs story failures, post-publication changes, observation windows.
- **Maintenance:** trigger precision/recall, context cost, installed-package links, stale sources, provider changes, migration, benchmark contamination.

## Deliberately deferred

Vector databases until keyword/tag retrieval fails on a real bank. Paid transcript services until manual ingestion is the bottleneck. Automated scraping until a specific acquisition route is reviewed and justified. Fine-tuning until explicit profiles and retrieval have a measured ceiling. npm packaging until executable functionality needs it. More personas until distinct tasks justify them.

## Release checklist

Run checks; read staged files; verify no private artifacts; record behavioral runs honestly; update changelog; commit; tag only a justified release; publish the GitHub repository; test documented install paths against that remote. A local foundation passing static checks is not a validated 1.0.
