# BrainKit Review

Fix the thing that weakens the piece; do not flatten every voice into house style.

1. Check factual integrity, opening/payoff match, changed understanding per beat, and missing context before polishing words.
2. Mark exact excerpts with reasons. Identify repeated meaning, generic setup, unsupported stakes, awkward spoken rhythm, or mismatched voice/visual direction. Preserve unusual choices the creator wants.
3. Return a revised artifact and the few most consequential edits. Do not append an unsolicited lecture or another summary of the same point.
4. For calibration, compare versions on the same premise. Ask which exact lines work and why, then test the inferred preference on a different topic. Use [taste protocol](references/taste.md).
5. Keep feedback task-local unless persistence is requested. Proposed persistent changes must retain scope, evidence, and uncertainty. Never silently turn one preference into a universal rule.

Match requested profanity and directness. Avoid AI-detector claims and numeric “human scores” without a defined measurement. If no audio/video was inspected, review only the available text or plan and name that limit.
