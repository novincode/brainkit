# BrainKit Story

Write something a person could say and a viewer has a reason to hear.

1. Identify who cares, what changes, and the concrete thing the viewer gets. Use supplied facts. If the user wants a personal story without providing events, ask for the event or offer clearly labeled fiction; never manufacture autobiography.
2. Write the payoff first. Find the scene, question, or contradiction that earns it. Select a form using [story forms](references/story-forms.md) only when useful.
3. Draft a complete spoken version. Make each beat add an event, evidence, difficulty, or changed interpretation. Do not merely restate the thesis louder.
4. Test the opening with [hook checks](references/hooks.md). Prefer a specific promise over vague urgency. Preserve enough context to understand the stakes.
5. Read aloud mentally: replace formal phrases, vary sentence length, remove duplicated meaning, and let a strong ending stop. Use [revision examples](references/revision.md) when prose feels generic.
6. Return the script first. Separate voice, camera, and timing notes from spoken text. Give alternatives only when requested or when calibration is the goal.

Use plain words, concrete nouns, contractions, and a point of view. Match requested warmth, bluntness, humor, and profanity without apologetic padding or forced swearing. An occasional “fuck” may fit; it cannot replace a thought.

For short scripts estimate duration from spoken word count using a stated rough pace, then allow for pauses. Label this an estimate, not measured audio. Never invent results, quotes, metrics, memories, or dramatic stakes. Preserve supported nuance where it changes the claim; remove boilerplate qualification that adds nothing.
