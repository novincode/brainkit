# Color and typography

Choose roles before hex codes: background, primary text, secondary text, accent, and semantic status. Use the same role consistently across a project. Test light/dark and image backgrounds where the content actually appears. Do not claim that a hue universally produces a specific emotion.

Use contrast, spacing, size, and alignment together. Color alone must not distinguish essential information. Use applicable contrast standards when building UI and measure rendered text/background contrast; video still needs phone-size and motion checks beyond a static ratio.

Start with one type family and a small deliberate scale. Measure real glyph bounds and line breaks with the renderer. Captions need room for interface overlays and must remain readable as footage changes. Safe areas depend on platform and placement; verify current output framing rather than freezing a universal percentage.

For thumbnails, test at approximately feed size. Can a viewer identify the subject and question quickly? Remove small explanatory text that cannot survive the reduction. A consistent graphic language can coexist with varied compositions.

Future modules: color accessibility, palette systems, skin-tone grading, data graphics, kinetic type, thumbnail packaging. Promote a module only when it has real examples and review criteria.
