# Taste protocol

Feedback is data about a person in a context, not a universal writing rule.

Capture exact excerpt, liked/disliked/neutral, reason in the creator's words, medium, topic, audience, strength, source, and date. Preserve contradictions until context explains them. “Too aggressive for this tutorial” is not “never use strong language.”

Start with three to six matched variants, then vary one dimension: scene-first vs claim-first; warm vs dry; restrained vs blunt; clean vs occasional profanity. Avoid changing topic, length, structure, and delivery all at once if trying to identify a cause.

Propose small rules such as “For tool tutorials, prefer a concrete failed attempt before the advice.” Keep one supporting and one rejected example. Check transfer on a new topic before raising confidence.

User-requested persistence can update a private profile plus an append-only feedback log. Do not include raw personal material in public defaults without explicit sharing intent. Corrections can narrow or revoke rules. Include a profile version so artifacts can identify which preferences they used.

No model weights change here. Improvement comes from better explicit instructions, selected examples, and retrieval.
